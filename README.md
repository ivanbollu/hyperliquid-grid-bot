# Hyperliquid 永续合约 自动交易机器人

一个跑在本机的 Hyperliquid 永续合约自动交易机器人，自带**网页交易台**，内置三套策略：

- **网格 + 马丁加仓**（`strategy: grid`）：在锚定价下方铺多层限价买单，成交后立刻挂 reduce-only 止盈单，
  止盈成交后该层复位重新挂单，在震荡行情里反复吃差价；越往下单量越大（马丁），用来摊低持仓成本。
- **触发单 / 条件单**（`strategy: trigger`）：只在指定价格买入或卖出一次，比如「ETH 到 2505 买 11 USDC」。
  不铺网格、不自动止盈，成交后仓位交给你手动管理。见「触发单策略」一节。
- **信号策略**（`strategy: signal`）：按 K 线算指标（默认 EMA 交叉 + 跟踪止损），出现信号就开仓，
  持仓期间盯着行情，该止损/止盈/反向交叉时**主动平仓**——这才是「根据行情变化实时买卖」。
  见「信号策略」一节。⚠️ 该策略已回测为**净亏**，默认干跑，请先看回测结论再决定。

---

## ⚠️ 先读这一段

- **这套策略不是稳赚的。** 网格吃震荡，马丁扛单边。行情单边下跌时马丁会不断加仓，
  亏损会快速放大——真正的防线是配置里 `risk` 段的熔断和持仓上限，**不要为了"想扛过去"把它们调大**。
- **所有实例默认 `dry_run: true`**，也就是只连真实行情、记账，但**不会真的下单**。
  请先让它跑一两个小时，确认挂单价位、层数、日志都符合预期，再改成 `false` 上真钱。
- **强烈建议用 API 钱包（Agent Wallet）而不是主钱包私钥**。API 钱包只能交易、不能提币，
  万一私钥泄漏，损失可控。见下文「配置 API 钱包」。
- **网页控制台没有任何登录鉴权**，所以默认只监听 `127.0.0.1`，外网访问不到。
  如果你改成 `--host 0.0.0.0`，请自己加一层反向代理 + 认证，否则等于把交易权限挂在公网上。
- 请先用**小资金**验证：`base_size` 调小、`max_total_notional_usd` 调小。
- 私钥只存在本机 `.env` 里，不要提交到任何仓库、不要发给任何人。
- 网页上的「连接钱包」是**纯只读**的：只读你的地址，不请求签名、不接触私钥，点错了也不会有资产风险。

## 快速开始

### 1. 安装依赖

```bash
cd hyperliquid-grid-bot
python -m venv .venv
# Windows:  .venv\Scripts\activate
# macOS/Linux:  source .venv/bin/activate
pip install -r requirements.txt
```

> 本机已经装好一个隔离环境，可以直接用：
> ```bash
> "C:/Users/vanbo/.workbuddy/binaries/python/envs/default/Scripts/python.exe" main.py web
> ```

### 2. 配置 API 钱包（强烈建议）

1. 打开 <https://app.hyperliquid.xyz/API>
2. 生成一个新的 **API 私钥**（Agent Wallet）
3. 把 API 私钥写进 `.env` 的 `HL_PRIVATE_KEY`
4. 在配置文件里把 `env.account_address` 填成 **主钱包地址**（不是 API 钱包地址）

```bash
cp .env.example .env
# 然后编辑 .env，填入 HL_PRIVATE_KEY=0x...
```

### 3. 启动网页交易台

```bash
python main.py web
```

浏览器打开 <http://127.0.0.1:8787> 。端口可用 `--port` 改。

## 网页交易台能做什么

| 区域 | 能力 |
| --- | --- |
| 顶栏 | 总账户权益、浮动盈亏、累计已实现、运行实例数；**连接钱包**；**全局急停**按钮 |
| 左侧列表 | 所有交易实例，状态灯（运行/空闲/熔断/错误）、干跑/实盘标签、实时盈亏 |
| 指标区 | 权益、净持仓、开仓均价、浮动盈亏、名义价值、**强平价**、挂单数、累计已实现、完成网格次数 |
| 风控条 | 名义持仓 / 上限、净持仓 / 上限、浮亏 / 熔断线 —— 三条进度条，接近红线会变黄变红 |
| 收益曲线 | 账户权益随时间变化（ECharts），每 30 秒采样一次，持久化到 `state/equity_<slot>.jsonl` |
| 网格层级 | 每层的挂单/持仓状态、数量、建仓价、止盈价 |
| 成交记录 | 建仓与止盈平仓明细，含每笔净盈亏 |
| 运行日志 | 实时日志尾巴，自动滚动 |
| 参数设置 | 表单化编辑全部参数，保存前做**合法性校验**，改高风险参数会二次确认 |
| 控制按钮 | 启动 / 停止（保留仓位）/ 撤单 / 一键平仓，全部带确认弹窗 |
| 钱包抽屉 | 连接钱包后查看该地址在 Hyperliquid 上的真实账户（见下节），一键绑定为交易账户 |

**多实例**：`configs/` 目录下每个 yaml 就是一个独立实例，可以同时跑多个标的、多套参数，
各自有自己的状态文件、日志、线程，互不干扰。点「＋ 新建实例」即可创建。

> 配置文件里手写的注释（`# ...`）在网页改参数、绑定钱包时**都会被保留**，写文件走的是行级改写，
> 不会整份重排。所以可以放心在 yaml 里写说明。

## 连接钱包（只读）

点顶栏右侧的「连接钱包」，用浏览器插件钱包（MetaMask / Rabby / OKX Wallet 等，任何符合
EIP-1193 的钱包都行）连上，就能在右侧抽屉里看到**这个地址在 Hyperliquid 上的真实账户**：

- 账户权益、可用保证金、占用保证金、名义敞口、未实现盈亏
- 永续持仓：方向、数量、开仓均价、标记价值、未实现盈亏、回报率、**强平价**、杠杆
- 交易所挂单（含只减仓 / 触发单标记）
- 现货余额、最近 60 笔成交、手续费等级
- 权益曲线（24 小时 / 7 天 / 30 天，来自官方 `portfolio` 接口）

### 它到底做了什么、没做什么

这是**纯只读**的，边界刻意画得很窄：

| 做 | 不做 |
| --- | --- |
| 向钱包请求「账户地址」（`eth_requestAccounts`） | ❌ 不请求任何签名（`eth_sign`/`personal_sign`/`signTypedData` 一个都不调） |
| 用这个地址调 Hyperliquid 的**公开** Info 接口 | ❌ 不接触私钥、助记词 |
| 把地址写进实例配置的 `env.account_address` | ❌ 不能、也不会把私钥写进配置 |

也就是说：**连接钱包不会给钱包任何授权，点错也没有资产风险**——它拿到的只是一个公开地址。

没装插件钱包也行：抽屉里可以直接粘贴地址来查看，功能完全一样（只是标记为「手动查看」）。

链不对（比如当前是 Ethereum 主网）会提示切到 Arbitrum One（Hyperliquid 入金网络）；
交易本身发生在 Hyperliquid 链上，切不切网不影响 bot 交易，只影响入金。

### 连不上钱包怎么办

按下面顺序排查（抽屉里的「**连接诊断**」会直接把当前状态列出来）：

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 顶栏显示「需在浏览器打开」 | 页面被**嵌在某个应用的预览窗口里**（IDE、桌面客户端的内嵌浏览器） | 插件钱包**不会注入到被嵌入的页面**，这是最容易被误判成"钱包坏了"的情况。抽屉里有地址复制/新窗口打开按钮，用 Chrome / Edge 打开即可 |
| 顶栏显示「未检测到钱包」，但你装了 MetaMask | ① 多个钱包插件抢注 `window.ethereum`；② MetaMask 被停用；③ MetaMask 装在**另一个浏览器**里 | 装好（或启用）后刷新；用装有 MetaMask 的那个浏览器打开；抽屉里能选具体要连哪个钱包 |
| 点连接后弹「已经有一个待处理的请求」 | 钱包里有挂起的弹窗没处理（`-32002`） | 点开浏览器右上角的钱包图标（会带红点），把那个请求处理掉再重试 |
| 点连接后没反应 | 钱包被锁定，或弹出窗口被浏览器拦截 | 先解锁钱包；检查浏览器的弹窗拦截设置 |
| 连接成功但看不到数据 | 后端查 Hyperliquid 失败 | 抽屉顶部会显示具体错误原文，不是白屏 |

> 这个页面**只认插件钱包（EIP-1193）**。手机浏览器的 App 内置 WebView 一般也没有插件钱包，
> 想要手机上看，直接在抽屉里粘贴地址即可（纯只读，功能完全一致）。

### 「绑定为交易账户」的作用

在钱包抽屉底部选一个实例，点「绑定」，就是把 `env.account_address` 设成这个地址。
配合 `.env` 里的 **API 钱包私钥**，bot 就会在**这个主账户**上下单——这是官方推荐的安全用法
（API 钱包只能交易不能提币）。绑错地址会被交易所直接拒单，不会有资金风险。

> 顺序建议：先在 <https://app.hyperliquid.xyz/API> 生成 API 钱包 → 私钥写入 `.env` →
> 网页连接主钱包 → 绑定到实例。绑定这一步会保留配置文件里所有注释。

## 命令行用法

网页控制台是主入口，命令行适合挂服务器常驻单实例：

```bash
python main.py web                    # 启动网页交易台
python main.py configs                # 列出所有实例配置
python main.py check   -c configs/eth-grid.yaml   # 自检：配置/网络/账户/参数体检（只读）
python main.py run     -c configs/eth-grid.yaml   # 前台运行单个实例
python main.py status  -c configs/eth-grid.yaml   # 查看账户与网格状态
python main.py cancel-all  -c configs/eth-grid.yaml
python main.py close-all   -c configs/eth-grid.yaml
python main.py reset-state -c configs/eth-grid.yaml
```

不加 `-c` 时默认取 `configs/` 下的第一个配置。

## 策略参数（`configs/*.yaml`）

| 参数 | 说明 |
| --- | --- |
| `env.dry_run` | `true` = 干跑（不下单），`false` = 真实下单 |
| `market.coin` | 交易对，如 `ETH` / `BTC` / `SOL` |
| `market.leverage` | 杠杆。网格不要开高杠杆，建议 3~5 |
| `market.base_size` | 每层基础下单量（以币计）。`check` 命令会打印预估名义价值 |
| `grid.mode` | `long` 做多网格 / `short` 做空网格 / `neutral` 双向网格 |
| `grid.anchor_price` | 锚定价，`0` = 启动时按当前中间价自动锚定 |
| `grid.step_pct` | 相邻网格间距（%）。太小→频繁成交但手续费吃掉利润；太大→半天不成交 |
| `grid.levels` | 层数 |
| `grid.take_profit_pct` | 每层止盈幅度（%），一般 >= `step_pct` |
| `martingale.multiplier` | 马丁倍数，`1.0` = 等量网格。建议先跑 1.0 或 1.2 感受一下 |
| `martingale.max_size_multiple` | 单笔最大放大倍数硬上限 |

### 触发单策略（`strategy: trigger`）

不想跑网格、只想「ETH 跌到某个价就买入」时用这个。把 `strategy` 改成 `trigger`，
网格那段参数就自动失效，只读 `trigger` 段：

| 参数 | 说明 |
| --- | --- |
| `trigger.side` | `buy` 买入 / `sell` 卖出 |
| `trigger.price` | 触发价。`limit` 模式=挂单价；`market` 模式=穿越判定价 |
| `trigger.size` | 下单数量（**以币计，不是 USD**） |
| `trigger.order_type` | `limit` = 限价单挂在盘口等成交；`market` = 价格穿越后立即市价成交 |
| `trigger.max_slippage_pct` | 仅 `market` 模式：市价单滑点容忍（%） |
| `trigger.once` | `true` = 成交后视为完成，不再补挂；`false` = 成交后重新挂单等下一轮 |
| `trigger.tp_pct` | `>0` 时成交后自动挂 reduce-only 止盈（%）；`0` = 只建仓，不止盈 |

⚠ **单笔名义价值必须 ≥ $10**，否则交易所直接拒单。`size` 要按触发价折算：
`size ≈ 目标金额 / price`，并向下/向上对齐到该币的步长（ETH 是 0.0001）。
例如「买入 11 USDC」在 2505 触发价下 ≈ `0.0044 ETH`（名义 $11.02），刚好稳过 $10 门槛。
`python main.py check` 会把折算后的名义价值打出来，下单前先跑一次。

现成的实例见 `configs/eth-buy-2505.yaml`（ETH 到 2505 买入）：

```bash
python main.py check   -c configs/eth-buy-2505.yaml   # 先看参数体检
python main.py run     -c configs/eth-buy-2505.yaml   # 跑起来（先保持 dry_run: true）
python main.py status  -c configs/eth-buy-2505.yaml
```

**两种挂单路径**（`limit` 模式）：

- 触发价 **低于** 现价 → 挂单挂在盘口等价格跌下来（`trigger 单：挂单中`），不成交。
- 触发价 **高于** 现价 → 挂出即成交（`触发单挂出即成交（价格已穿越触发价）`）。

成交后触发单任务标记为「已完成」，进程会继续跑以便实时看浮盈，确认无误后手动停止即可。
下次重新启动前如果想再挂一次，先 `reset-state` 清掉「已完成」标记，否则不会重新下单。

### 信号策略（`strategy: signal`）—— 真正「根据行情实时买卖」

网格和触发单都是**挂单等成交**，成交就结束了，不会主动平仓。
信号策略是一个完整的「开仓 → 持有 → 平仓」循环，这才是「跟着行情走」：

```
每根 K 线收盘后算指标（不用未收盘那根，避免信号重绘）：

  金叉（快线上穿慢线）+ 趋势过滤通过 → 开多
  死叉（快线下穿慢线）              → 平多 / （allow_short 时）开空

持仓期间三条出场路，谁先到谁生效：
  1. 跟踪止损：止损价 = 持仓期最有利价 − max(trail_pct%, ATR×atr_mult)
               创新高时止损自动上移，回撤到止损价就市价平掉
  2. 反向交叉：出现相反方向的交叉立即平仓
  3. 固定止盈：take_profit_pct > 0 时启用
```

⚠️ **先把这句话读三遍：这个策略在当前行情下是亏钱的，不要上真钱。**

`tools/backtest.py` 实测（ETH 15m / 最近 32 天 / 3073 根 K 线）：

| 指标 | 数值 |
| --- | --- |
| 交易次数 | 25 |
| 胜率 | 16%（4 胜 / 21 负） |
| 毛收益（未扣费） | **-0.3325 USDC** |
| 手续费合计 | 0.1650 USDC |
| 净收益 | **-0.4975 USDC** |
| 同期「买了不动」 | +2.86%（+0.3141 USDC） |
| 前后两段分别跑 | -0.2745 / -0.1599（两段都亏） |
| 24 组参数扫描 | 仅 1 组微弱为正（+0.0086），且其后半段 -0.0600 |

原因不是引擎写错了，而是：**手续费（往返 0.03%~0.09%）+ 震荡行情里的反复假信号**。
这个引擎的价值在于「正确执行信号」，至于信号赚不赚钱，必须靠回测说话。

参数表（`signal` 段）：

| 参数 | 说明 |
| --- | --- |
| `signal.interval` | K 线周期：`1m`/`5m`/`15m`/`30m`/`1h`。5m 只有约 17.5 天历史，15m 约 30 天，1h 约 60 天 |
| `signal.candles` | 取多少根已收盘 K 线算指标，必须 `> slow_ema`，建议 300 |
| `signal.candle_cache_sec` | K 线缓存秒数，别设太小（省接口额度） |
| `signal.fast_ema` / `slow_ema` | 快线 / 慢线周期，`slow_ema` 必须大于 `fast_ema` |
| `signal.trend_ema` | `>0` 时只在收盘价位于该长期均线同侧才开仓（趋势过滤），`0` = 关闭 |
| `signal.entry_mode` | `maker` = 挂在回撤价等成交（0.015% 费率）；`taker` = 立即市价（0.045%） |
| `signal.entry_offset_pct` | maker 模式：买单挂现价下方、卖单挂上方这么多 |
| `signal.entry_ttl_sec` | 挂单多少秒没成交就撤掉，等下一次信号 |
| `signal.allow_short` | 死叉时是否反手做空 |
| `signal.atr_period` / `atr_mult` | 跟踪止损距离 = `max(百分比, ATR × 倍数)`，取更宽的那个 |
| `signal.trail_pct` | 跟踪止损百分比 |
| `signal.take_profit_pct` | `>0` 时到价止盈；趋势策略通常 `0`（只用跟踪止损） |
| `signal.exit_on_cross` | 反向交叉立即平仓 |
| `signal.size` | 下单数量（币）。**名义必须 ≥ $10** |
| `signal.max_rounds` | 最多做几轮（一轮 = 开 + 平），`0` = 不限。先设小值试探 |

现成的实例见 `configs/eth-trend.yaml`（ETH 15m，EMA 12/48，默认干跑）：

```bash
python tools/backtest.py --interval 15m --days 31          # 不先跑这个就等于闭着眼睛下注
python tools/backtest.py --interval 15m --days 31 --sweep  # 扫描快慢线 / 止损组合
python main.py check -c configs/eth-trend.yaml
python main.py run   -c configs/eth-trend.yaml             # 保持 dry_run: true 先观察
```

## 网格回测（决定「该做哪个方向」的那块拼图）

`tools/grid_backtest.py` 用真实历史 K 线算网格到底赚不赚钱，和信号回测一样**只看已收盘 K 线、按 maker 计费、
复现名义上限风控**，并且额外遵守一条防虚高的规则：**同一根 K 线内刚买入的仓位不允许在本根止盈**
（否则会出现「用最低价买、用最高价卖」的假利润）。

```bash
python tools/grid_backtest.py --interval 15m --days 30            # 默认参数
python tools/grid_backtest.py --interval 1h --days 60 --anchor rolling   # 价格跑出区间就重锚
python tools/grid_backtest.py --no-martingale                     # 关掉马丁对比
python tools/grid_backtest.py --anchor rolling --sweep            # 扫 step × levels
```

**实测结论（2026-10-12，务必先读再上钱）：**

| 发现 | 数据 |
| --- | --- |
| **固定锚定会「停摆」** | 30 天里价格涨到 2716 后，8 层全部落在市价下方，后半段回调到 2551 都没跌回第 1 层 → **零成交**。配置 `reanchor: false` 时就是这个状态 |
| **盈亏几乎由锚点决定** | 同参数、同长度 15 天窗口，只换起跑位置：8 个窗口 **4 正 4 负**，最好 +6.13、最差 -9.42、中位 +0.19 |
| **调窄格距 = 加杠杆，不是改进** | step 0.3% 让正收益窗口 4/8→5/8，但最差窗口 -9.42→**-15.82**、最大浮亏 -24→**-31** |
| **名义上限提到 $1000 就够** | $500→$1000 只多赚 1.04 USDC；$2000 无进一步效果（峰值名义只到 $547） |
| **统一口径（账户 1000 USDC）** | 30 天（+1.05%）：网格 +8.49 / **躺平 +10.50**；60 天（+34.61%）：网格 +9.72 / **躺平 +346.08** |

**核心结论：网格在任何上涨行情里都跑输躺平**，连近似横盘（30 天 +1.05%）也跑输 2 块。这不是参数问题，是数学必然：
网格赚「波动幅度」，躺平赚「趋势涨幅」，而 ETH 长期向上 —— 网格天然在跟趋势对赌，**只在真横盘里才有优势**。

同一时期另外三个方向也一并验过：**跨所套利**结构性不可行（1000 USDC 拆两半、价差覆盖不了两边费 + 提币费、
毫秒级机器人在抢、还有单腿风险）；**资金费率套利**实测年化仅 ETH 8.40% / BTC 8.51%，1000 USDC 一年约 84，不值得建系统；
**趋势跟随** 1h 三组参数全亏（-16.78 / -13.31 / -19.96），放宽止损反而亏更多。

## 行情诊断（每天该做什么、别做什么）

`tools/market_brief.py` 把当前市场状态量化成一段人话。**它不是预测，不构成投资建议。**

```bash
python tools/market_brief.py                                              # 只看行情
python tools/market_brief.py --config configs/eth-grid.yaml --margin 200  # 带上你网格的价位
python tools/market_brief.py --coin BTC
```

它做四件事：

| 维度 | 怎么算 | 回答什么 |
| --- | --- | --- |
| **趋势** | 15m / 1h / 4h 三周期 EMA20/50/200 排列，按周期加权打分（−6 ~ +6） | 现在偏多、偏空还是震荡？三个周期是否一致？ |
| **波动率** | ATR(14) 占价格的百分比，在近 30 天里的分位 | 网格有没有肉吃？止损会不会轻易被打到？ |
| **区间位置** | 现价在近 30 天【收盘价 5%~95% 分位】区间中的位置 | 该加仓还是该减仓？ |
| **资金费率** | 近 7 天累计年化 | 持有多头/空头的成本高不高？ |

然后按「趋势 × 波动 × 位置」的组合，分别给出**网格 / 加仓 / 减仓**三类建议，
并单独列出**「现在别做的事」** —— 那部分往往比建议本身更有用。

> 区间位置用**收盘价分位**而不是最低 low / 最高 high：单根 K 线的长影线会把区间撑大，
> 拿它切出来的"买入参考价"会明显偏低。（脚本里两个口径都会打印。）

**边界**：它不能告诉你明天涨还是跌。它能做的是拦住你在错误的位置做错误的动作 ——
比如涨到区间上沿去追多、跌到爆仓线附近还加仓、在低波动环境里指望网格赚钱。

## 从 0 到上真钱：执行顺序与仓位基准

### 执行顺序（顺序错了会白亏手续费）

```bash
# 1) 充值：把 USDC 提到【主钱包】（Arbitrum 网络，地址见网页右上角 Deposit）
#    目标金额 = 想买现货的 ETH + 网格保证金 + 一点缓冲

# 2) 先买现货 ETH，再启动网格 —— 反过来网格会先把钱铺成挂单
python tools/buy_spot_eth.py --usd 700          # 预览：会买多少、花多少（不下单）
python tools/buy_spot_eth.py --usd 700 --yes    # 确认无误后才真下单

# 3) 核对网格要占多少保证金（改任何网格参数前都先跑这个）
python tools/grid_plan.py --margin 200 --stress

# 4) 保持 dry_run: true 干跑 1~2 小时，确认挂单价/层数/日志符合预期

# 5) 再改 dry_run: false 上真钱
python main.py run -c configs/eth-grid.yaml
```

### 仓位基准 · 以 `configs/eth-grid.yaml`（200 USDC 保证金 / 5x）为例

| 项目 | 数值 |
| --- | --- |
| 8 层全部成交 | 持仓 **0.3182 ETH**，均价 ≈ **$2431**，累计名义 ≈ **$774** |
| 峰值占用保证金 | ≈ **$155**（占 200 的 77%） |
| 全层成交后爆仓价 | ≈ **$1830**（较现价 −28.3%，维持保证金率按 1.5% 估） |
| `max_total_notional_usd` | 必须 ≥ 全层累计名义，否则深处几层挂不出去（旧值 500 会卡在第 7 层） |

**⚠ 现货 ETH 那部分是纯裸多**：它不占网格保证金，网格的浮亏熔断也**管不到它**。
所以「700 买 ETH + 200 做网格」本质是**双倍做多 ETH**，不是分散风险 ——
涨的时候两边都赚（这是它能跟上趋势的原因），跌的时候两边一起亏（这是它比单做网格更疼的原因）。

## 风控参数（不要随手调大）

| 参数 | 作用 |
| --- | --- |
| `max_total_notional_usd` | 名义总持仓上限。超过就不再开新仓 |
| `max_position_size` | 单标的净持仓上限（币） |
| `max_unrealized_loss_usd` | **浮亏熔断线**。触发后：撤掉全部挂单 → 市价平仓 → 停机冷却 |
| `min_account_value_usd` | 账户权益低于此值 → 平仓停机 |
| `max_open_orders` | 同时挂单数量上限 |
| `max_daily_orders` | 每日下单笔数上限（防止 bug 空转刷单） |
| `cooldown_after_stop_sec` | 熔断后冷却时间。冷却期内重启会被拒绝 |

熔断是**一次性动作**：平完仓就停机，必须人工确认后重启（冷却期内还要先在网页上「清除本地状态」）。

### ⚠️ 统一账户（unifiedAccount）与权益读数

Hyperliquid 新账户默认是**统一账户**：USDC 存在**现货**侧，但可以直接当永续保证金用。

这种账户下，**现货 USDC 与永续 `accountValue` 是同一笔钱的两个视角，不是两笔钱**：

| 场景 | 永续 accountValue | 现货 USDC（total / hold） | 真实权益 |
|---|---|---|---|
| 无持仓无挂单 | `$0.00` | `$19.38 / $0.00` | **$19.38** |
| 只挂单（占用 $2.22） | `$2.22` | `$18.69 / $2.22` | **$18.69** |
| 满仓占用 | `$18.96` | `$18.96 / $18.96` | **$18.96** |

看第三行：永续那个数字**恰好等于现货被冻结（hold）的部分**，也就是从现货划出去当保证金的那笔钱。
所以两者**只能取较大值，绝不能相加** —— 相加会把权益算成两倍，风控直接失效
（机器人以为还有 $38，实际只剩 $19，该熔断时不会熔断）。

机器人已按「取较大值」实现，`python main.py check -c configs/xxx.yaml` 会打印拆分：

```
账户模式 : unifiedAccount
账户权益 : $18.69  (统一账户：永续 $2.22 / 现货 USDC $18.69，二者为同一笔钱，取较大值)
```

### ⚠️ 手工仓 / 其它策略的仓位不会干扰本策略

同一个账户里可能同时有手工开的仓、或者别的策略在跑。机器人只认**本配置 `market.coin` 的仓位**：

- `total_notional`（受 `max_total_notional_usd` 约束）只统计**本标的**的名义价值
- `unrealized_pnl`（受 `max_unrealized_loss_usd` 约束）只统计**本标的**的浮盈浮亏
- 熔断平仓只平本标的（`close_position(coin)`），撤单只撤带本 bot cloid 标签的单

否则手工开的 BTC 空单（名义约 $599）会立刻顶爆 `max_total_notional_usd: 500`，
或者它一浮亏就把 ETH 的仓一起熔断掉。

**权益下限会在「挂单之前」就检查。** 权益低于 `min_account_value_usd` 时，启动会被直接拒绝并给出原因，
不会再出现「先买入、几秒后又被熔断市价平仓」这种白亏手续费和价差的情况。

> 参考量级：名义 $11、5 倍杠杆的单子只占用约 **$2.20** 保证金。
> 如果只是做小额测试，`min_account_value_usd` 设成 20 很容易卡住；设 5~10 通常更合适。

## 它怎么工作的

**一个网格层的生命周期**

```
待建仓 (pending)  --价格跌到该层价，限价买单成交-->  持仓中 (open，同时挂好止盈单)
      ^                                                      |
      |                                                      | 价格反弹到止盈价，止盈单成交
      +------------------------------------------------------+
                        该层复位，重新在原始层位挂买单
```

**对账机制**：每轮循环拉一次交易所挂单列表，比对本地状态。发现自己的订单不见了就去查成交记录：
有成交 → 结转仓位/盈亏；没成交 → 判定被外部撤销，重新挂。
所以**手动去网页上撤单、手动加仓，bot 都能感知**（手动挂的单它不会碰，只会在日志里提醒你）。

**重启恢复**：状态存在 `state/<slot>.state.json`。重启后拿真实挂单和持仓对账，
不会重复下单，也不会漏掉停机期间发生的成交。

**干跑模式**：用真实行情做本地撮合模拟（限价单穿越即成交，含手续费），逐笔打印"干跑成交"，
并给出同样的风控保护。注意它不模拟排队、滑点和资金费率，所以结果偏乐观。

## 常见问题

**Q: 网页打不开？**
确认 `python main.py web` 还在运行，浏览器访问 <http://127.0.0.1:8787>。
端口被占用可以 `--port 8888`。

**Q: 报错 "下单失败：价格/数量精度"？**
`base_size` 或价格算出来精度不够。ETH 的 `szDecimals=4`，价格最多 2 位小数；
BTC 的 `szDecimals=5`，价格最多 1 位小数。bot 会自动按规则取整，取整后为 0 就会报这个错——把 `base_size` 调大。

**Q: 启动后一层单都没挂？**
大概率被风控拦了，日志里会写明原因（"名义持仓将超上限"/"多头持仓将超上限"）。
按提示调 `max_total_notional_usd` 或 `max_position_size`。命令行 `check` 能看到参数体检结果。

**Q: 网页上改了参数没生效？**
保存后需要重启实例才生效。实例运行中不允许改配置。

**Q: 能不能手动在网页上操作？**
可以。手动撤单/加仓 bot 都能对账。但它只管理自己挂的单，你手动挂的限价单它不会碰。

**Q: 收益曲线为什么是空的？**
实例运行后每 `equity_interval_sec`（默认 30 秒）采样一次，跑几分钟就有数据了。

**Q: 点「连接钱包」没反应 / 显示"未检测到钱包"？**
最常见的原因**不是没装钱包，而是页面被嵌在某个应用的预览窗口里**——插件钱包为防止点击劫持，
不会注入到被嵌入的页面，所以永远检测不到。这种情况顶栏会直接显示「需在浏览器打开」，
抽屉里有地址复制和新窗口打开按钮。
如果是普通浏览器，按上面「连不上钱包怎么办」的表格逐条排查；
抽屉的「连接诊断」一栏会列出运行环境、检测到的钱包、`window.ethereum` 状态，照着看即可。
实在不行也不用装插件 —— 抽屉里直接粘贴地址，一样能查看该账户。

**Q: 连接钱包会不会有被盗风险？**
不会。这个页面只调用 `eth_requestAccounts` 拿地址，不请求任何签名、不碰私钥；
钱包插件在授权时也不会给出转账权限。真要防的是别在别处泄漏私钥。

**Q: 为什么连上钱包后显示的账户和顶部「总账户权益」不一样？**
两回事：顶部 KPI 是**本机 bot 实例**的汇总（未运行的实例不参与），
钱包抽屉是**该地址在链上的真实账户**（包含你手动开的仓、其它工具的仓位）。

**Q: 我在网页上改了参数，配置文件里的注释会不会被清掉？**
不会。写回走的是行级改写，只动真正变化的那些行，其余（含注释、对齐、空行）原样保留。

## 风险再强调一遍

马丁格尔的数学性质决定了：它大概率赚小钱、小概率亏大钱。
`max_unrealized_loss_usd` 是你唯一真正踩得住的那道刹车。请把它设成一个
「亏掉也完全不影响生活」的数字，然后**不要因为想扛单而去改它**。
